# Mouse Museum — коллекция Михаила Павлова

Рабочий образец независимого двуязычного каталога компьютерных мышей. Английский по умолчанию, русский — по переключателю. Полностью перенесены все 305 публичных экспонатов и 1 967 фотографий. Сборка содержит 715 страниц на двух языках. Сохранены 1 966 оригиналов; для одной фотографии Tandy Combi Mouse (ID 53) источник возвращает HTTP 403, поэтому сохранено доступное превью 1000 × 666. Подробности — в `reports/collectionerus-sync.md`.

## Посмотреть сразу

Распакуйте архив и откройте `dist/index.html` в браузере. Каталог, фильтры и страницы карточек работают без установки программ и без интернета. Все фотографии и стили входят в архив. Ссылки для форумов становятся публичными после размещения сайта; до публикации кнопки копируют локальный адрес. В некоторых браузерах копирование из локального файла ограничено: тогда появляется выделяемое текстовое поле.

Для просмотра через локальный HTTP-сервер из папки проекта:

```bash
python3 -m http.server 8000 --directory dist
```

После запуска откройте http://localhost:8000/.

## Что реализовано

- Каталог с настоящими фотографиями, поиском, фильтрами по производителю, десятилетию, технологии, интерфейсу и СССР.
- Четыре порядка сортировки: кураторский, год вверх/вниз, название.
- Состояние фильтров в URL. Переключение EN/RU сохраняет фильтры.
- Отдельные готовые HTML-страницы каждого экспоната на обоих языках.
- Галерея, увеличение фотографий, переключение стрелками в увеличенном просмотре.
- Постоянная ссылка, BBCode, Markdown, BBCode с изображением.
- Адаптивная вёрстка: три колонки на широком экране, две на узком; фильтры на телефоне раскрываются кнопкой.
- Название и описание каждой страницы; при сборке с публичным адресом — canonical, hreflang, Open Graph, sitemap и robots.txt.
- Навигация с клавиатуры, подписи форм, сообщения об изменении количества результатов и пустой выдаче.
- Никаких сторонних шрифтов, аналитики, CDN, API или загрузки данных во время просмотра.

## Что лежит в проекте

| Путь | Назначение |
| --- | --- |
| `content/mice/` | Один JSON на экземпляр: данные, переводы, ссылки на фотографии |
| `assets/photos/` | Оптимизированные WebP и отдельные миниатюры |

| `scripts/check.py` | Проверка внутренних ссылок и структуры HTML |
| `.github/workflows/pages.yml` | Автоматическая сборка и публикация |
| `dist/` | Готовый сайт; включён в архив для просмотра, исключён из Git |

Данные и фотографии находятся в GitHub. При изменении репозитория GitHub Actions однократно запускает генератор и передаёт папку `dist` в GitHub Pages. После сборки Python нигде не работает: посетитель получает только HTML, CSS, JS и изображения. База данных и постоянно работающий сервер не нужны.

## Первая публикация на GitHub Pages

1. Создайте публичный репозиторий с именем `mouse-archive`. Публичный репозиторий позволяет использовать GitHub Pages на GitHub Free. Для приватного репозитория нужна поддержка Pages вашим тарифом.
2. Загрузите **содержимое** папки проекта в корень репозитория, включая `.github/workflows/pages.yml`. Не загружайте внешний ZIP как единственный файл. Надёжнее открыть папку проекта в GitHub Desktop и опубликовать её; `dist` и `.openai` исключаются через `.gitignore`.
3. Используйте ветку `main`. Если имя другое, измените `branches` в workflow.
4. Откройте Settings → Pages → Build and deployment → Source → GitHub Actions.
5. На вкладке Actions выберите Publish Mouse Archive → Run workflow → main → Run workflow. Следующие изменения в `main` публикуются автоматически.
6. Дождитесь успешного выполнения workflow. Точный адрес сайта появится в Settings → Pages и в результате задания публикации.

Для запуска не нужны токены в исходниках и секреты вручную: workflow использует штатные permissions GitHub Actions. Доступ к репозиторию и настройка Pages в этой версии не выполнялись; live-публикация и работа в реальном GitHub Actions ещё не проверены.

Ссылки в страницах относительные, поэтому сайт поддерживает как репозиторий в подпапке github.io, так и отдельный домен. Публичный базовый адрес берётся из `actions/configure-pages`; от него строятся абсолютные Open Graph URL и карта сайта.

## Как обновлять коллекцию

Существующая карточка: откройте соответствующий JSON в `content/mice`, нажмите Edit на GitHub, измените значения, сохраните коммит. Разметку менять не требуется. Фотографии также можно загрузить через интерфейс GitHub.

Новый экземпляр:

1. Создайте отдельную папку в `assets/photos/` с устойчивым коротким английским названием.
2. Добавьте WebP-фотографии примерно до 1600 px по длинной стороне и `thumb.webp` примерно до 600 px. Исходники полного разрешения храните в своём фотоархиве отдельно.
3. Скопируйте `content/mice/microsoft-green-eye.json` в новый JSON и замените все поля на реальные данные нового экземпляра. Идентификатор `id` и адрес `slug` должны быть уникальными. `slug` не следует менять после публикации: на него будут ссылаться форумы.
4. В `photos` перечислите все нужные снимки. Код поддерживает произвольное количество снимков. Названия файлов указываются относительно корня проекта. При использовании собственных новых снимков поле `source` у фотографии можно оставить пустой строкой.
5. В `description.en` и `description.ru` можно добавить краткое описание; в `notes` — комментарии к конкретному экземпляру. HTML в текстах не исполняется.
6. Сохраните изменения. Workflow соберёт обновлённый сайт.

Поле `year` содержит целое число или `null`, если дата не указана в источнике (9 карточек). Неизвестные годы доступны отдельным пунктом фильтра и идут последними при сортировке в обоих направлениях. Поле `interface` может быть `null`. Фильтры автоматически строятся из карточек. Списки свойств и переводов находятся в JSON, а тексты самого интерфейса — в генераторе.

`sourceProperties` — сохранённые поля исходного сайта для сверки. Они не используются как публичный каталог: основными после миграции являются отдельные структурированные поля. Служебные места хранения вроде «Дальний» и «Ближний» не показываются посетителям. Для полной коллекции удобно вынести исходные служебные сведения в закрытый учёт, если они не должны попасть в публичный Git.

Значения характеристик перенесены из источника, а не заново исторически верифицированы. В карточке NeXT N4000A явно отмечена необходимость проверки года и интерфейса исходной записи. Перед публикацией полного международного каталога стоит проверить подобные поля, унифицировать названия производителей, отделить интерфейс от формы разъёма, тип устройства от технологии и сведения о модели от особенностей конкретного экземпляра.

Идентификаторы `MP-0003` и подобные — предложенная схема: префикс коллекции плюс номер исходной записи. Это не заводские серийные номера. Бренд Mouse Archive и английские тексты — рабочая концепция.

В шаблоне явно отмечено, что перед нами образец. Перед полноценным запуском замените эти тексты на окончательные в `scripts/build.py`, проверьте контактные данные и сведения о коллекционере. Фото и исходные данные принадлежат их правообладателям; проект не объявляет их свободной лицензией.

## Размеры и хранение

GitHub Pages допускает опубликованный сайт до 1 GB; для исходного репозитория рекомендовано не более 1 GB. Мягкое ограничение трафика — 100 GB в месяц. Поэтому хранить полноразмерные многомегабайтные оригиналы всех фотографий в этом репозитории нецелесообразно.

Оценка для планирования: 305 карточек × 6 фотографий × 200 KB ≈ 366 MB, плюс 305 миниатюр × 40 KB ≈ 12 MB и разметка. Это не измерение полной коллекции: фактический размер зависит от числа снимков и качества сжатия. 10 снимков по 400 KB на каждый экспонат уже дадут примерно 1,22 GB. Перед полным переносом нужно измерить суммарный размер. История заменённых бинарных файлов увеличивает размер Git-репозитория, даже если опубликованный сайт остаётся небольшим.

При росте достаточно перенести изображения в объектное хранилище/CDN, оставив каталог статическим. Это не требует введения backend-приложения. Пока помещаемся в лимиты, всё можно хранить непосредственно в GitHub.

Вместо номеров страниц каталог постепенно показывает порции по 30 карточек. Следующая порция открывается автоматически за 200 px до конца списка, также доступна кнопка «Показать ещё». При исчерпании результатов кнопка исчезает. Изображения загружаются лениво средствами браузера; данные карточек уже входят в статическую HTML-страницу, серверное API не требуется. Проверены SHA-256, полное декодирование каждого оригинала, размеры по исходным галереям, весь порядок фотографий, данные и ссылки. Аудит: `python3 scripts/test_source_sync.py`. Также выполнены остальные проверки сайта и просмотр полной галереи из 13 фотографий в браузере.

Оригиналы и доступное изображение источника занимают 3 169 461 174 байта, вся сборка — около 3,67 GiB. Для публикации потребуется учесть объём изображений и ограничения выбранного хостинга. ### Публикация без оригиналов фотографий

Пока оригиналы не публикуются: сборка исключает каталоги `originals` и `source-images`, карточки не содержат ссылок на них. Увеличенный просмотр использует WebP для просмотра. Исходники и метаданные оригиналов сохранены локально для последующего подключения внешнего хранилища.
