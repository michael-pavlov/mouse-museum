# Как редактировать журнал

Текст каждой публикации хранится в Markdown, отдельно по языкам:

- `mindset-mouse/ru.md` — русский текст;
- `mindset-mouse/en.md` — английский перевод.

Остальные статьи устроены так же. Откройте нужный `.md` на GitHub, нажмите Edit и сохраните изменения. При настроенной публикации GitHub Actions соберёт сайт автоматически.

Дата, название, короткое описание для ленты, обложка и связи с экспонатами находятся в соседнем JSON, например `mindset-mouse.json`. Поле `bodyFiles` указывает на Markdown-файлы. Чтобы связать статью с экспонатом, добавьте его `slug` в `relatedItems`: обратная ссылка в карточке появится сама. Опубликованные `slug` менять не следует.

## Текст и фотографии

```markdown
Первый абзац. **Жирное выделение**, *курсив* и [ссылка](https://example.com).

![Механизм мыши](../../../assets/posts/mindset-mouse/02.webp)

Следующий абзац продолжается под фотографией.

## Подзаголовок

![Плата мыши](../../../assets/posts/mindset-mouse/03.webp "Подпись под фотографией")

- Первый пункт
- Второй пункт

> Цитата.
```

Каждое фото ставьте отдельным абзацем: оставляйте пустую строку до и после. Порядок в Markdown — это порядок на сайте. Отдельной автоматической галереи и обязательного фото в начале больше нет. Обложка ленты задана отдельно и на расположение снимков в статье не влияет.

`![Описание фото](путь)` — описание для доступности. Необязательный текст в кавычках после пути выводится как подпись под фото. По клику фотография открывается целиком. Размер вписывается в ширину статьи, без обрезки.

Путь считается от самого Markdown-файла. Из `content/posts/mindset-mouse/ru.md` путь `../../../assets/posts/mindset-mouse/02.webp` ведёт в папку изображений в корне проекта. Такие пути также работают в предпросмотре GitHub. Новую фотографию достаточно загрузить в `assets/posts/<slug>/` и вставить её путь в Markdown; для вывода внутри статьи перечислять её в JSON не требуется. Поле `photos` сохраняет сведения об импортированных снимках.

Для ссылок на экспонаты можно использовать исходные ссылки Collectionerus: если экземпляр уже перенесён, сборщик автоматически заменит их ссылками на локальные карточки соответствующего языка. Это не создаёт связь `relatedItems` автоматически: список упомянутых экземпляров задаётся в JSON.

## Локальная проверка

Один раз установите зависимость сборки:

```bash
python3 -m pip install -r requirements.txt
```

После редактирования из корня проекта:

```bash
python3 scripts/build.py
python3 scripts/check.py
python3 scripts/test_journal.py
```

Отсутствующая фотография останавливает сборку с сообщением о пути файла. Сайт остаётся статическим: Markdown преобразуется в HTML только при сборке, посетителю не нужны дополнительные библиотеки или серверное приложение.

## Импорт архива Telegram

В журнал добавлены все 61 авторская запись, доступная в публичной истории канала на дату переноса. Снимки источника, английские переводы новых постов и анонсы хранятся в `data/source/telegram/`. Подробный отчёт и команды повторного переноса: [telegram-import.md](../../reports/telegram-import.md).

У импортированных фотографий поле `original` указывает на неизменённый JPEG, который открывается при увеличении. Необязательное поле `videos` содержит локальные видео вида `{"file":"assets/posts/telegram-115/video-01.mp4","source":"https://…"}`. Они выводятся с управлением воспроизведением. Поля `mediaNote` и `archiveNote` содержат пояснения EN/RU о недоступном видео или материалах в комментариях.

Исключения из публикации задаются в `content/journal-exclusions.json`: указанные исходные ссылки не попадают в ленту, страницы статей и обратные ссылки на экспонатах. Список учитывается при повторном импорте. Исходные тексты и медиа остаются в архиве проекта.
